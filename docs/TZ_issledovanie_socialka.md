## 1. Цель и границы

**Цель этапа 1:** Акт I «Каркассон» играется в Point_NRI от собрания в Париже до доклада Ролану (БТ-01).
Мастер ведёт, движок считает: каждый расчёт — предложение, которое мастер принимает, перебрасывает, правит или отменяет (Р1).

**В этапе 1:** время и путь по карте региона, встречи и засады, еда, вода, отдых, истощение, состояние героя между боями;
проверки навыков, инструменты, языки, цена небоевых умений; NPC, отношение, деревья диалогов, репутация; деньги, вещи,
лавки, торг, сведения и выплаты; панель мастера в комнате; чтение кампании из Obsidian.

**Не в этапе 1:** опыт и уровни (этап 2, БТ-05), прыжки через кристаллы (ПУТ-14), языковая модель за NPC,
запись в Obsidian (кроме экспорта журнала), поправки цен по странам.

**Бой не меняется** (НФ-02): в режиме арены всё работает как сейчас; новое включается только в режиме кампании.

## 2. Архитектура

```
Obsidian (только чтение)            web/play_server.py                         build/kampaniya (C++)
 карточки NPC, вещей, заданий  ──►  web/kampaniya.py:                    ──►  src/apps/kampaniya.cc
 деревья диалогов                    загрузка markdown → JSON содержимого       держит состояние = свёртка журнала,
 таблицы встреч Акта I               журнал state/kampaniya/<id>/journal.jsonl   считает правила (src/engine/explore.h,
                                     роль мастера в комнате, видимость           social.h, trade.h), бросает кости
                                         │
                                         ▼  сцена → бой: arena_play с начальным состоянием героев
                                     web/js/60_kampaniya.js (игрок), 61_master.js (мастер)
```

- **Правила — только в C++** (НФ-03): проверки, путь, отдых, истощение, цены, торг, каскад выплат. Python хранит журнал,
  читает Obsidian, раздаёт видимость; страница рисует.
- **`build/kampaniya`** — отдельная программа, как `arena_play`: строки JSON в stdin/stdout. `arena_play` не трогаем,
  кроме начального состояния героев (задача Б6).
- **Состояние = свёртка журнала** (НФ-01). Журнал — `jsonl`, одна строка — одно событие. Сервер при запуске кормит программе
  журнал целиком, дальше — по событию. Отмена (МАС-06) — свёртка без последнего события.
- **Кости:** `Rng(hash(зерно кампании, номер события, номер броска))`. Переброс — новое событие, новый номер, новый бросок.
  Повтор журнала даёт то же состояние до бита.

### 2.1. Цикл «предложение → решение мастера»

1. Игрок или мастер просит действие (`kmp_propose`): «следующий день», «спросить Ролана о болоте», «купить коня».
2. Программа считает **черновик** события (броски, итог) и не применяет его.
3. Мастер: **принять** (событие пишется в журнал и применяется), **перебросить** (новый черновик), **править** (мастер меняет
   поля итога; пишется событие с пометкой `правка`), **отменить**.
4. Действия мастера напрямую (МАС-04) — сразу событие `мастер`, без черновика.
5. Скрытый бросок (МАС-07) — у события поле `скрыто`: игрокам уходит только «мастер бросил».

## 3. Данные

### 3.1. События журнала

Общие поля: `n` (номер), `t` (время мира: день, час), `кто` (мастер / имя игрока), `тип`, `броски` (`[{к:20, выпало, мод, сл, итог}]`), `скрыто`, `правка`.

| Тип | Что меняет |
|---|---|
| `старт` | зерно, карта региона, отряд, стартовые деньги и вещи |
| `день` | время +1 день; путь за день, расход еды и воды, траты на жизнь, навигация, бросок встречи (всё одним событием) |
| `переход` | позиция отряда, часы (часть дня, форсированный марш) |
| `проверка` | итог проверки навыка/характеристики; ссылка на узел диалога, если есть |
| `встреча` | таблица, строка к12, участок мира (зерно, x, y, размер) |
| `бой` | состояние героев после боя (ХП, ячейки, применения, истощение), павшие, добыча |
| `отдых` | короткий/долгий: восстановление по Р9 |
| `еда`, `поиск` | запасы еды и воды |
| `сделка` | кошельки, инвентарь, лавка NPC |
| `сведения` | отряд узнал факт; или сдал (выплата по каскаду) |
| `отношение`, `репутация` | NPC к отряду; фракция к отряду |
| `диалог` | текущий узел разговора |
| `мастер` | любое прямое действие (поля — что поменял) |
| `заметка` | текст в журнал, ничего не меняет |

### 3.2. Состояние героя (новое поле персонажа `сост`)

`{хп, хпВрем, ячейки:[использовано по уровням], применения:{id способности: использовано}, истощение, голод:{дней без еды},
вода, кости_хитов}` + `инвентарь:[{вещь, число, надето}]`, `кошелёк` (в медных). В режиме арены поля нет — бой как сейчас.

### 3.3. Форматы Obsidian (ДАН-02)

Путь к хранилищу и папки — `config/kampaniya.json`:
`{"хранилище": "~/Documents/Учёба/Obsidian_Vault/Компейн - Аномалии планов", "npc": "Мир/Персонажи", "акт": "Сюжет/Акты/Акт I — Каркассон.md", ...}`.
Сущность определяется полем `тип` во frontmatter. Файлы без `тип` игра не трогает: существующие заметки кампании остаются как есть.

**NPC:**
```yaml
---
тип: npc
имя: Ролан
уровень: 5                      # или бюджет: 271
фракция: Корона Франции
языки: [старофранцузский, латынь]
отношение: безразличный          # дружелюбный | безразличный | враждебный, внутри шкала −2…+2
навыки: {Проницательность: 3, Убеждение: 5}   # итоговые модификаторы, если нет сборки
знает: [болотные-признаки]
лавка: []                        # [{вещь: паёк, цена: 5 см, есть: 50}]
диалог: "[[Ролан — приём]]"
сборка: "[[Ролан.json]]"         # необязательно: персонаж char_spec для боя и проверок
---
```

**Дерево диалога** (заголовок второго уровня — узел; строка `Имя: «…»` — реплика; пункты — варианты; `!` — действие):
```markdown
---
тип: диалог
npc: "[[Ролан]]"
начало: приветствие
---
## приветствие
Ролан: «Вас вызвали последними. Слушайте внимательно.»
- Спросить об аномалии → аномалия
- [Проницательность 15, скрыто] Понять, что он недоговаривает → болото | приветствие
- [Убеждение 20] Попросить аванс больше → аванс-больше | отказ
- [если: язык латынь] Заговорить по-латыни → латынь

## болото
Ролан: «У Каркассона видели признаки чего-то болотного.»
!сведения: болотные-признаки
→ аванс

## аванс
!дать: 100 зм отряду
!конец
```
Синтаксис варианта: `[Навык СЛ(, скрыто)(, отношение)] текст → успех | провал`; `[если: условие]` — показывается только при
условии (язык, отношение ≥, сведения, деньги ≥); `!дать`, `!взять`, `!сведения`, `!отношение ±N`, `!репутация фракция ±N`,
`!бой [[сборка]]`, `!лавка`, `!конец`. Без `|` провал ведёт в тот же узел. СЛ без числа — по таблице реакций DMG (§4.5 требований).

**Вещь:**
```yaml
---
тип: вещь
имя: Длинный меч +1
цена: 1000 зм
вес: 3
редкость: редкий
открывает: оружие длинный меч   # какой атом сборки работает при этой вещи (Р7)
атомы: {weapon: {magic: true, hitB: 1, dmgB: 1}}   # фрагмент char_spec — свой бюджет вещи (Р8)
---
```
Каталог обычных вещей PHB — `web/data/veshchi.json` (в проекте, не в Obsidian): имя, цена, вес, что открывает.

**Задание** (каскад выплат Акта I, ТОР-10):
```yaml
---
тип: задание
имя: Экспедиция Ролана
аванс: 100 зм
сведения: {аномалия: 1000 зм}
шаг: 0.9            # каждая следующая новая сдача — от предыдущей
подтверждение: 0.5  # от текущей ступени
предметы: {нижний-кристалл: 1500 зм, верхний-кристалл: 1500 зм}
соперники: 455      # отрядов; порядок их возвращения ведёт мастер или бросок
---
```

**Таблицы встреч (ДАН-03)** читаются из файла акта **как написаны**: таблица со столбцами «Местность | Порог встречи (к20)»,
разделы `### <Местность>` с таблицей «к12 | Встреча», таблица «Местность | Где засада | Кто». Правила «на дороге +2»,
«обратный путь −4, засада на 1–3» — параметры в `config/kampaniya.json`, по умолчанию как в Акте I.

## 4. Задачи

### Группа А. Проверки, навыки, инструменты, языки

**А1. Проверка** (`src/engine/explore.h`, НАВ-01, НАВ-02). Функции `check(герой, навык|характеристика, сл, преим)`,
`passive(…)`, `contest(…)`, `groupCheck(…)`. Модификаторы — из той же сборки, что в бою: характеристика, `skillProf`,
`skillExp`, правило «когда → что» `what 16`, истощение. Проверка возвращает все слагаемые — их показывает журнал.
Тесты: экспертиза = мастерство ×2; пассивная с преимуществом = +5; групповая — половина; истощение 1 — помеха (`T210–T214`).

**А2. Инструменты по названиям** (НАВ-03) [БОЙ]. `tools` — список названий из каталога PHB; число в старых файлах
читается как «N безымянных» (цена та же). Конструктор: выбор из списка с поиском (как навыки).
Проверка с инструментом: +мастерство; навык и инструмент вместе — преимущество (XGE, Р22).

**А3. Языки** (НАВ-04, Р17) [БОЙ]. Поле персонажа `langs` — список; каталог: языки D&D + наречия из `kampaniya/karty/langs.py`
(выгрузить список в `web/data/yazyki.json` один раз, скриптом; сам `kampaniya/` не читать во время игры). Цена — по А4.
«Общего» в каталоге нет: его роль играет латынь, у NPC она пишется явно.

**А4. Цена небоевых умений** (НАВ-05, НАВ-06, Р4, Р5) [БОЙ]. Атом 94 остаётся базой. Добавить в `core.h` таблицу весов
`NCW[]` (14 небоевых навыков, инструмент, язык), стартовое значение 1.0 — цена не меняется, пока владелец не задаст веса.
Цена = `P(AT_SKILLNC) × NCW[k] × мастерство/2` (язык — без множителя мастерства). Новых атомов не добавлять: индексы атомов
видят Сборщики [ПРОВЕРИТЬ, что `NCW` не входит в их наблюдение]. Проверить, что `gen_boss.h:269` и Сборщики не покупают
небоевое; тест: смена `NCW` не меняет `quick_check.sh` (`T215`).

**А5. Отчёт частоты проверок** (НАВ-08). `tools/ncw.py <журналы…>` → таблица «навык → проверок на час игры → предложенный вес».
Вес в код — только решением владельца (как `bake.py`).

**А7. Атом «восстановление»** (НАВ-09, Р16) [БОЙ]. У способности с применениями, у ячеек, легендарного сопротивления,
всплеска действий, запаса костей — поле `восст`: `бой` (по умолчанию, как сейчас) / `короткий` / `долгий`. Цена ресурса ×
`C[восст]`: старт ×1 / ×0,8 / ×0,6 (Р20), уточнение — по журналам кампании (как А5). В арене ресурс полный каждый бой
и множитель не действует — цена полная (Р21); в кампании — со скидкой; лист героя показывает обе цены. Генератор и Сборщики
всегда `бой` → `quick_check.sh` совпадает. Это новый атом: добавить **в конец** `AD[]` и проверить, что Сборщики
не видят его в наблюдении [ПРОВЕРИТЬ `builder_net.h`]. Тест `T228`.

**А6. Небоевые заклинания** (НАВ-07, S). Эффект способности «вне боя» с параметром (обнаружить магию, понимание языков,
разговор с животными, поиск пути, обнаружение мыслей…): в бою недоступен, в кампании — действие с проверкой или без.
10 заготовок из `Sushnost/Sushnost/spells`. Цена — по Р4 через вес `NCW`.

### Группа Б. Время, путь, тело

**Б1. Карта региона** (ПУТ-01). Общий формат `region.json`: места `{id, имя, x, y, вид}`, отрезки `{a, b, км, местность, дорога}`.
Два поставщика: (1) Европа 1208 — скрипт `tools/region_europe.py` один раз выгружает из `kampaniya/karty/geodata/routes.json`
и данных городов в `web/data/region_europe.json` (единственный допуск к `kampaniya/` — этот скрипт, по указанию владельца);
(2) мир из шума — из плана **того же** мира, где идут сцены (Р19, задача В3): поселения, дороги, реки; местность —
по крупному слою биомов и высоте (§4.3 требований).

**Б2. Прокладка пути** (ПУТ-02, ПУТ-03, ПУТ-04). Отряд задаёт точки; между точками — по отрезкам или напрямик по местности.
Скорость дня = канон (тип путника по самому медленному в отряде) × местность × темп. Тест: пеший 35 км по дороге и ~17 по лесу (`T216`).

**Б3. День** (ПУТ-05, ПУТ-06, ПУТ-07, ПУТ-09, ТОР-08). Событие `день` одним черновиком: пройдено, местность большей части дня,
навигация (если вне дороги), бросок встречи, расход еды и воды, траты на жизнь, проверки голода и жажды, форсированный марш
по желанию. Мастер правит любое поле. Встреча → строка таблицы → мастер решает: сцена, бой, разговор или пропуск.
Тесты: пороги Акта I; дорога +2; обратный путь −4 и засада на 1–3 (`T217–T219`).

**Б4. Отдых** (ПУТ-11, Р9, Р13, Р16). Кости хитов: число = уровень (до этапа 2 — уровень по бюджету из кривой ×1,08),
к8 + мод. ТЕЛ за кость, не покупаются. Короткий: ресурсы `восст: короткий`, траты костей хитов по выбору игрока. Долгий:
все ХП, половина костей хитов, ресурсы `короткий` и `долгий`, раз в 24 ч, −1 истощение при еде и воде. После каждого боя —
ресурсы `восст: бой`. Поправка гонки Акта I «−2 за долгий отдых» — по журналу. Тест `T220`.

**Б5. Истощение** (ПУТ-18, Р12) [БОЙ]. Одно состояние героя 1–6 на поход, погоню и бой: 1–5 — эффекты погони как сейчас,
6 — смерть. В арене истощение по-прежнему возникает только в погоне, эффекты 1–5 те же → эталон боёв совпадает. Тест `T229`.

**Б6. Состояние между боями** (ПУТ-12) [БОЙ]. `arena_play` принимает у персонажа необязательный `сост` (§3.2): начальные ХП,
израсходованные ячейки и применения, истощение. После боя отдаёт их обратно. Без `сост` — как сейчас; эталон совпадает
[ПРОВЕРИТЬ, где в `char_spec.h`/`fight.h` задаются начальные ХП и счётчики применений]. Тест `T221`.

**Б7. Поиск пропитания, ездовые животные** (ПУТ-10, ПУТ-13, S). Поиск — Выживание добытчика по изобилию местности. Конь —
вещь со скоростью пути, ест, в бою не участвует (этап 1).

**Б8. Роли в пути** (ПУТ-16, Р18). Перед днём каждый герой выбирает занятие: проводник (навигация, Выживание), дозорный
(пассивная Внимательность против засад и встреч), добытчик (пропитание), картограф (+2 проводнику на следующий день по
этой местности, открывает карту), следопыт (Выживание по следам), помощь (преимущество тому, кому помогает). Кто не дозорный —
не замечает угроз; быстрый темп −5 к пассивной Внимательности. Роли — часть события `день`. Тест `T230`.

**Б9. Груз** (ТОР-03, Р15). Вес инвентаря и запасов против 15 × СИЛ фунтов (размер: ×2 за ступень крупнее среднего, ½ у
крошечного); сверх — скорость −10 фт в сцене и бою, в походе только медленный темп.

### Группа В. Сцена на мире из шума

**В1. Участок по местности** (ПУТ-08). В `world_gen.h` функция `findSite(plan, местность, зерно, размер)`: детерминированный
поиск участка нужного биома/уровня/признака (река, поселение) по зерну встречи. Таблица соответствия — §4.3 требований.
Тест: одно зерно — тот же участок; лес → ≥60% клеток «лес и поля» или тайга (`T222`).

**В2. Сцена без боя.** Участок показывается всем (как карта боя), герои ставятся рядом; можно ходить, открывать двери,
разговаривать; бой начинается из сцены кнопкой мастера или `!бой` диалога. Сцены-загадки (нижний кристалл) — мастер ведёт сам;
движок даёт проверки (ЛОВ для выхода из воронки) и опасные зоны, которые уже есть.

**В3. Большой мир** (ПУТ-17, Р19) [БОЙ]. `world_gen.h` сейчас строит план целиком: сетка высот с шагом 16 клеток и
сетки отрезков с шагом 64 на весь мир; `arena_play` и `arena_map.h` режут размер до 10 000. Для мира до 400 000 клеток:
- план — **кусками по запросу** (куски, например, 4096×4096 клеток с кэшем последних); реки и дороги, идущие через куски,
  строятся на грубом плане региона (шаг, например, 1 км) и уточняются в куске;
- **крупный слой** температуры, влажности и высоты (частоты в десятки км) складывается с нынешними для миров больше 10 000:
  тогда биомы — пояса, а не рябь;
- плотность поселений и рек — по-прежнему на км², виды поселений — по населению из «Масштабов» (деревня … великий город);
- **миры до 10 000 клеток — те же до бита**: новый путь включается только для размера больше 10 000 (проверка — эталон и
  тест «тот же участок по тому же зерну» на 1000, 3000, 10 000);
- память ≤ 1 ГБ, построение участка сцены ≤ 2 с на ноутбуке владельца [ПРОВЕРИТЬ замером].
Тест: мир 400 000, зерно X — участок одинаков при двух запусках; доля биомов на карте региона — связные области ≥ 5 км (`T231`).

### Группа Г. Деньги, вещи, торговля

**Г1. Кошельки и инвентарь** (ТОР-01, ТОР-02, ТОР-03). Деньги в медных; кошелёк героя и отряда; передача; вес — Б9.

**Г2. Вещь открывает атом** (ТОР-04, Р7) [БОЙ]. В режиме кампании перед боем сервер передаёт в `arena_play` только оружие
и доспех, вещи которых есть у героя (оружие без вещи убирается из арсенала, очки не возвращаются; без доспеха КД считается
без него). Связь атома и вещи — поле `вещь` у оружия и доспеха в `char_spec` (имя из каталога); без поля — «любая подходящая».
В режиме арены не проверяется. Тест `T223`.

**Г3. Магический предмет** (ТОР-05, Р8) [БОЙ]. Фрагмент `атомы` вещи сливается со сборкой героя перед боем; цена фрагмента
считается тем же кодом, что цена персонажа (`tools/calc.py` / движок). Лист героя: «бюджет уровня N + предметы M = сила N+M».
Тест: меч +1 добавляет к цене столько же, сколько те же атомы в сборке (`T224`).

**Г4. Лавка и торг** (ТОР-06, ТОР-07). Лавка из карточки NPC и каталога; покупка, продажа за половину; магия в лавке не
продаётся. Торг (Р14): состязание Убеждения / Обмана / Запугивания против Проницательности торговца, ±10% за каждые
5 разницы, предел ±30%; проигрыш на 10+ — отношение −1; Запугивание — отношение −1 после сделки всегда. Тест `T232`.

**Г5. Награды** (ТОР-09). Калькулятор мастера по формуле справочника; итог — событие `мастер` (дать деньги).

### Группа Д. NPC и разговоры

**Д1. Карточки NPC** (РАЗ-01). Загрузка по §3.3; модификаторы проверок NPC — из `сборка`, иначе из `навыки`.

**Д2. Отношение** (РАЗ-02). Три ступени, внутри шкала −2…+2; таблица реакций DMG; изменения — событиями.

### Группа Е. Сведения

журнал с фильтром; отмена последнего события (МАС-06); экспорт журнала в markdown (МАС-08).

**Ж4. Экран игрока** (`web/js/60_kampaniya.js`). Карта региона с отрядом и путём, лист героя (ХП, истощение, еда, кошелёк,

### Группа З. Obsidian

**З1. Загрузчик** (`web/kampaniya.py`, ДАН-01…ДАН-06). Чтение frontmatter и markdown без внешних библиотек (как `mini_json`);
